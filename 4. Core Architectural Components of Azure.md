### Region, Region Pair and Sovereign Regions
##### Region
A Region in Microsoft Azure is a geographical area that contains a group of data centers used to host cloud services. These data centers work together to provide high availability and low latency for users. Organizations choose a region based on factors like performance and compliance. For example, a company with users in India may deploy its application in the India region so users experience faster access. (Central India)
##### Region Pair
A Region Pair is when two Azure regions within the same geography are linked together to support disaster recovery and reliability. These regions are connected through high-speed networks, allowing data to be replicated between them. If one region fails, the other can continue to run the application. For example, if an application is hosted in one region and that region goes down, the paired region can take over and keep the service available. (North Europe paired with West Europe)
##### Sovereign Regions
A Sovereign Region is a special type of Azure region that is isolated from the main public cloud and designed for organizations with strict security and regulatory requirements. These regions are commonly used by governments or industries that must keep data within a specific country. Access is restricted and requires approval. For example, a government agency may use a sovereign region to ensure that sensitive national data does not leave the country. (Azure Government or Azure China)
### Availability Zones and Data Centers
Availability Zones in Microsoft Azure are physically separate locations within a single region, each made up of one or more data centers. These zones are isolated with independent power, cooling, and networking, so a failure in one zone does not impact the others. They are used to increase high availability and fault tolerance by distributing applications across multiple zones.

However, not every Azure region supports Availability Zones, and not every service supports them. 
There are three types of Availability Zone services:
- Zonal services:
  Zonal services are deployed into a specific Availability Zone that you choose within a region in Microsoft Azure. This gives you control over where your resources run, which can help with performance or latency requirements. However, they do not provide automatic protection against zone failures, so if that zone goes down, you must design and implement failover to another zone yourself. (Example - Virtual Machine)
- Zone-redundant:
  Zone-redundant services are automatically distributed across multiple Availability Zones within the same region. Azure handles data replication and failover, so if one zone fails, the service continues to operate from other zones without interruption. This approach is ideal when you want high resilience and availability without needing to manually manage failover mechanisms. (Example: Azure SQL Database)
- Always available:
  Always available services (also called non-regional services) are not tied to a specific region or Availability Zone. Instead, they are designed to be globally available and resilient to both zone-level and region-level failures. Services like Microsoft Entra ID or Azure Front Door fall into this category, as they continue to function even if an entire region becomes unavailable.
### Resources and Resource Groups
##### Resource
Resources in Microsoft Azure is a general term used to represent any service you create and use, such as a virtual machine, storage account, or database. Each resource has a name defined by you, and in some cases, the name must be globally unique (like storage accounts), while in others it only needs to be unique within a scope. When creating a resource, you also typically choose the region where it will be deployed.
##### Resource Groups
A Resource Group is a logical container used to organize and manage related resources in Azure. It helps you group resources that belong to the same application or project so they can be managed together. A resource group is associated with a specific region, but the resources inside it can exist in different regions. You can also assign permissions at the resource group level, making it easier to control access for multiple resources at once. However, a resource group does not act as a security boundary for communication, meaning resources inside it can still communicate with resources outside it unless additional networking controls are applied.
### Subscriptions
A Microsoft Azure subscription is a logical container for Azure resources, used to organize, govern, and bill for cloud services. It acts as an administrative boundary for access control, policy enforcement, and compliance, helping organizations manage resources consistently. All resources created within a subscription are tracked together for usage and billing.

Users can have access to multiple subscriptions, and they can have different roles in each subscription (for example, admin in one and reader in another).
For example, a company may use separate subscriptions for development, testing, and production to manage costs, control access, and enforce different policies.
### Management Groups
Management Groups in Microsoft Azure are used to organize multiple subscriptions into a hierarchy, making it easier to manage access, policies, and compliance at scale.

They sit above subscriptions and allow you to apply governance (policies, access control, compliance rules) across multiple subscriptions at once instead of configuring each one individually. Management groups can also be nested (one inside another) to create a hierarchy, but the structure supports a maximum of 6 levels.

For example, a company can create management groups for Production and Development and place subscriptions under them. If the company wants encryption enabled on all virtual machines, it can apply a policy at the management group level, and it will automatically apply to all subscriptions and resources under that group.

```
In Microsoft Azure, the physical infrastructure is organized in a hierarchy. At the lowest level are data centers, which are the actual physical facilities hosting servers and hardware. Multiple data centers can form an Availability Zone, which provides isolation with separate power, cooling, and networking for high availability. Multiple Availability Zones together make up a region, which is a geographical area where Azure services are deployed. At a higher level, regions are linked as region pairs, providing disaster recovery and high-speed connectivity between two regions within the same geography.

Aslo, resources are organized in a hierarchy to simplify management and governance. At the lowest level are resources (like virtual machines or storage accounts), which are grouped into resource groups for easier management. These resource groups are contained within a subscription, which acts as a boundary for billing, access control, and governance. At the top level, multiple subscriptions can be organized into management groups, allowing policies and permissions to be applied across all subscriptions and their resources in a structured and scalable way.
```
