### Compute Services
Compute services in Microsoft Azure are services that provide processing power to run applications, code, or workloads in the cloud.
In simple terms, compute services are the “brains” that execute your programs, whether it’s a website, application, or background process.

Azure offers different types of compute services depending on how much control you want:
- Virtual Machines - Full control over OS and environment
- App Services - Run applications without managing servers
- Functions (Serverless) - Run code only when triggered
- Containers / Kubernetes - Run and manage containerized apps
#### Virtual Machine (VM)
A Virtual Machine (VM) in Microsoft Azure is a virtual (software-based) computer that runs on the cloud.
It behaves just like a physical computer - you can install an operating system, applications, and software, and have full control over it.

It works by dividing a powerful physical machine into multiple virtual “slices” using virtualization technology. Each slice is assigned to a different customer, and it behaves like a separate, independent computer, even though it is running on shared hardware. To the user, it feels like they are using their own dedicated system.
#### Scaling Azure VMs
To handle changing demand, Virtual Machines in Microsoft Azure can be scaled either manually or automatically. Instead of managing individual VMs one by one, Azure provides a more efficient way to scale using Virtual Machine Scale Sets.
##### Virtual Machine Scale Sets
Azure Virtual Machine Scale Sets allow you to deploy and manage a group of identical virtual machines.
They are designed for applications that need to scale automatically based on demand or predefined rules:
- Automatically add VMs (scale out) when traffic increases
- Automatically remove VMs (scale in) when demand decreases
- All VMs in the set are identical and load-balanced
- Helps maintain high availability and performance

Example:
A website normally runs on 2 VMs.
- During high traffic, VMSS automatically increases to 10 VMs
- When traffic decreases, it scales back to 2 VMs
#### Availability Sets and Proximity Groups
##### Availability Sets
Availability Sets in Microsoft Azure are used to increase the availability of multiple identical Virtual Machines (VMs) by distributing them across different parts of the underlying hardware. These VMs usually run the same application (like multiple web servers) so that if one fails, others can continue serving users.
- Fault Domain:
  A Fault Domain represents a group of VMs that share the same physical hardware (like power source or network switch). By placing VMs in different fault domains, Azure ensures that a hardware failure affects only some VMs, not all.
  For example, if you deploy 3 identical web server VMs in an availability set and one hardware rack fails, only one VM is affected while the others keep running.
- Update Domain:
  An Update Domain represents a group of VMs that are updated or rebooted together during planned maintenance. Azure updates one update domain at a time, so other VMs remain running, ensuring minimal downtime.
##### Proximity Groups
Proximity Groups in Microsoft Azure are used to place VMs physically close to each other within a data center.
This is useful for applications that require low latency and high-speed communication between components, such as real-time processing or high-performance computing.

For example, if an application has multiple VMs that need to communicate very quickly, placing them in a proximity placement group ensures they are located near each other, reducing network delay.
#### App Services, Containers and Azure Virtual Desktop
##### App Services
Azure App Service is a PaaS (Platform as a Service) offering in Microsoft Azure that allows you to host web apps, APIs, and backend services without managing servers.
You simply upload your code, and Azure takes care of infrastructure, scaling, patching, and maintenance. It also provides built-in features like auto-scaling, CI/CD integration, custom domains, and staging environments.

Example:
You deploy a website on App Service, and Azure automatically scales it when traffic increases—no need to manage VMs.
##### Containers
Containers package an application along with all its dependencies (code, libraries, runtime), so it runs consistently across environments. Azure provides multiple container services depending on your needs:
- Azure Container Instances (ACI):
  Run containers quickly without managing servers. Best for simple or short-lived workloads.
  Example: Run a background job container for a few minutes.
- Azure Container Apps (ACA):
  Fully managed platform for running microservices and APIs with auto-scaling and event-driven capabilities.
  Example: A web app made of multiple small services that scale automatically.
- Azure Kubernetes Service (AKS):
  Advanced container orchestration platform for large-scale, complex applications. You manage container clusters, scaling, and networking.
  Example: A large enterprise application with many interconnected services.
##### Azure Virtual Desktop
Azure Virtual Desktop is a service that lets you run Windows desktops and applications in the cloud and access them remotely.
Users can connect from anywhere and use a full desktop experience as if they were using a local computer, while everything actually runs in Azure.

Example:
A company provides employees with secure remote desktops, so they can work from home without storing data on personal devices.
#### Azure Function
Azure Functions is a serverless compute service in Microsoft Azure that lets you run small pieces of code (functions) without managing servers.
It is designed for small, specific tasks, so there is no need to create and manage an entire Virtual Machine just to run a simple operation.

You simply write your code, and it runs only when triggered by an event, such as an HTTP request, file upload, timer, or message queue.

Example:
A simple example of Azure Functions is when a user uploads a file, and a small piece of code automatically runs to process it, like resizing an image or sending a notification.
### Azure Networking Services
A Virtual Network (VNet) in Microsoft Azure is a private network in the cloud that allows your resources (like Virtual Machines, databases, etc.) to communicate securely with each other.
By default, two Virtual Machines in Azure cannot communicate with each other - they don’t even know about each other. A Virtual Network is required to connect them and enable communication.
Example
A company creates: 2 Virtual Machines and 1 database
All are placed inside a VNet, so they can talk to each other securely, and the database is not exposed to the internet.

Key Points:
- Provides secure communication between resources
- Required for resources to connect with each other
- Can be connected to on-premises networks
- Supports subnets, IP addressing, and security rules
##### Network Security Group (NSG)
A Network Security Group (NSG) in Microsoft Azure is a security layer used to control network traffic to and from your resources.

It works like a firewall, allowing or blocking traffic based on rules you define.
#### Network Peering, Azure DNS and VPN Gateway
##### Virtual Network Peering
Peering in Microsoft Azure (specifically Virtual Network Peering) is a way to connect two Virtual Networks (VNets) so they can communicate with each other privately.
##### Azure DNS
Azure DNS is Microsoft’s managed DNS hosting and resolution service for domains and virtual networks. It lets you host public DNS zones, manage private DNS for Azure VNets, and integrate name resolution with other Azure and on-premises resources.
##### Azure VPN Gateway
Azure VPN Gateway is used to create a secure, encrypted connection between your on-premises network and Azure over the internet. (need to install physical VPN client on-premise and install VPN gateway at Azure site)
It allows you to safely connect your local office network to your cloud network.
Example:
A company connects its office network to Azure so employees can securely access cloud resources as if they were in the office.
##### Azure ExpressRoute
Azure ExpressRoute provides a private, dedicated connection between your on-premises network and Azure, without using the public internet.
It is faster, more reliable, and more secure than VPN.
Example:
A large enterprise uses ExpressRoute to connect its data center to Azure with a high-speed private connection for critical applications.
### Public and Private Endpoints
Whenever you create a resource in Microsoft Azure (like Storage, SQL DB, Key Vault), you must decide how it will be accessed.
There are 3 main ways:
- Public Endpoint (All Networks):
  In Microsoft Azure, a public endpoint with access from all networks means your resource is available over the internet using a public IP address. Anyone can reach the resource from anywhere, but they still need proper authentication (keys, credentials, etc.) to actually access it. It is easy to use and suitable for public-facing applications, but the resource is exposed and discoverable on the internet, which may not be ideal for sensitive data.
- Public Endpoint (Selected Networks – Service Endpoints):
  In this approach, the resource still has a public endpoint, but access is restricted to specific Virtual Networks or IP ranges. Only resources inside the allowed networks can connect, while all other traffic is blocked. Communication from these approved networks travels through Azure’s private backbone network, improving both security and performance. This method provides controlled access without fully removing the public endpoint.
- Private Endpoint:
  A private endpoint completely removes public access and assigns a private IP address inside your Virtual Network (VNet) to the resource. This means the resource can only be accessed from within your private network, and all traffic stays inside Azure’s network using Azure Private Link. It provides the highest level of security, as the resource is not exposed to the internet at all, making it ideal for sensitive or critical applications.
