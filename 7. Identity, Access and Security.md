### Identity and Microsoft Entra ID
##### Identity
Identity simply means “who a user or system is” in any computing environment. It is how systems recognize users and decide whether they are allowed to access something. Identity is usually verified using something the user knows (password), has (phone/token), or is (biometric).
##### Microsoft Entra ID
Microsoft Entra ID is a modern cloud-based identity provider in Microsoft Azure that centralizes authentication and authorization.

Before modern cloud identity systems, organizations used Active Directory, where user accounts were stored centrally and applications verified logins using protocols like LDAP and NTLM. Each application often had to rely on this directory to confirm user identity.
Modern identity systems like Microsoft Entra ID remove the need for each application to store passwords. Instead, Entra ID acts as a central identity provider, and applications trust it to handle authentication securely.

It supports modern standards such as OAuth 2.0, OpenID Connect, and SAML. OAuth is used for delegated access (apps access resources without sharing passwords), while SAML is commonly used for Single Sign-On (SSO), where one login works across multiple trusted applications.

In this model, the Identity Provider (IdP) is responsible for verifying users, so applications do not manage credentials directly. This improves security, simplifies management, and enables seamless access across cloud and on-premises systems.
### Benefits of Microsoft Entra ID
- Microsoft Entra ID provides a centralized way to manage user identities and access across cloud and on-premises applications in Microsoft Azure.
- One of the main benefits is Single Sign-On (SSO), which allows users to sign in once and access multiple applications without repeatedly entering credentials. This improves user experience and reduces password fatigue.
- It also provides strong security features like Multi-Factor Authentication (MFA), conditional access policies, and risk-based sign-in protection, which help prevent unauthorized access even if passwords are compromised.
- Another benefit is centralized identity management, where all user accounts, roles, and permissions are managed in one place. This makes it easier for organizations to control access across multiple applications and enforce consistent security policies.
- Entra ID supports integration with modern and legacy systems, including cloud apps using OAuth/OpenID Connect and enterprise systems using SAML or Active Directory integration, making it flexible for hybrid environments.
### Authentication and Authorization
##### Authentication
Authentication is the process of verifying who a user is. It confirms the identity of a person or system before allowing access. This is usually done using credentials like a username and password, multi-factor authentication, or identity providers such as Microsoft Entra ID.

Example: When you log in with your email and password, the system checks if you are really who you claim to be.
##### Authorization
Authorization happens after authentication and determines what a user is allowed to do. Even if a user successfully logs in, they may not have permission to access all resources or perform all actions.

Example: After logging in, a user may be allowed to view data but not delete it, based on their assigned role or permissions.
### External Identities (Entra ID B2B and B2C)
External Identities in Microsoft Entra ID is a feature that allows organizations in Microsoft Azure to securely give access to people outside their organization without creating internal user accounts for them.
These external users can be partners, contractors, vendors, or customers, and they can use their own identity (like company account, Google, or Microsoft account) to sign in.

This approach improves security, simplifies user management, and provides easier access experience.
##### B2B (Business to Business)
B2B (Business-to-Business) is used for collaboration between organizations. Here, you invite external users (like partners or consultants) into your Azure environment as guest users.
They are added to your directory but still use their own company credentials to sign in. Once added, you can assign them roles and permissions just like internal employees, but with controlled access.

Example:
A company hires an external consulting firm. Instead of creating new accounts, they invite consultants as guests so they can access specific resources securely.
##### B2C (Business to Consumer)
B2C (Business-to-Consumer) is used for customer-facing applications. These are users who are not part of your organization but use your application, such as customers of an e-commerce website.
Instead of building your own login system, Azure allows users to sign in using social accounts like Google, Facebook, or Microsoft accounts, or create their own credentials.

Example:
An online shopping website lets customers sign in using Google or email instead of managing passwords itself.
### Azure AD Conditional Access
Conditional Access in Microsoft Entra ID is a security feature that controls how and when users can access applications in Microsoft Azure based on risk signals.
It works on the idea that not every login attempt is equally safe, so Azure evaluates each sign-in and decides whether to allow, block, or require extra verification.

Example:
When a user tries to log in, Conditional Access checks multiple signals like:
- User identity (who is logging in)
- Location (country or IP address)
- Device type (trusted company device or unknown device)
- Application being accessed
- Risk level of the sign-in
Based on these signals, Azure decides the action.

- A user logs in from the office using a company laptop (normal behavior) - Access is allowed directly
- A user logs in from a new country or unknown device - Azure may ask for extra verification (MFA)
- A login attempt from a high-risk location or suspicious activity - Access is blocked completely
### Multi-Factor Authentication
Multi-Factor Authentication (MFA) in Microsoft Entra ID is a security method that requires a user to verify their identity using more than one type of authentication factor when signing in to Microsoft Azure.
It makes accounts more secure because even if one factor (like a password) is stolen, an attacker still cannot access the account without the other factors.
##### Authentication Factors
MFA is based on three types of identity verification:
- Something you know → Information only the user knows (password, PIN, passphrase, security questions)
- Something you have → A physical or digital item owned by the user (OTP on phone/email, authentication app, smart card, hardware token)
- Something you are → Biometric identity (fingerprint, face recognition, iris scan, voice recognition)
##### Available MFA methods in Azure
- Microsoft Authenticator app → approves sign-in via mobile app notification
- Authenticator Lite (Outlook) → built-in Outlook approval for sign-ins
- Windows Hello for Business → uses device-based biometric/PIN login
- FIDO2 security key → physical USB/NFC key for password-less login
- OATH hardware token → physical device that generates OTP codes
- OATH software token → app that generates OTP codes
- SMS → sends one-time code to mobile phone
- Voice call → verifies identity via automated phone call code
### Password-less
Password-less authentication in Microsoft Entra ID is a sign-in method where users do not use a password at all to access resources in Microsoft Azure. Instead, they authenticate using stronger and more secure methods like biometrics, mobile apps, or security keys.

It improves security by removing passwords completely, which reduces risks like phishing, password reuse, or weak passwords.
### Role-Based Access Control (RBAC)
Role-Based Access Control (RBAC) in Microsoft Entra ID is a system used in Microsoft Azure to control who can access what resources and what actions they can perform.
Instead of giving full access to everyone, RBAC assigns roles to users, groups, or services, and each role defines a set of permissions. This helps improve security by following the principle of least privilege (only give the access needed).
##### Basic RBAC Roles
Reader → Can only view resources, no changes allowed
Contributor → Can create and modify resources, but cannot manage access permissions
Owner → Full control over resources, including managing access for others
### Zero-Trust Model of Security
The Zero-Trust model in Microsoft Entra ID is a security approach used in Microsoft Azure where no user, device, or network is automatically trusted, even if they are inside the organization. Every access request must be verified continuously before granting access.
This model assumes that threats can exist both inside and outside the network, so security is enforced at every level.
##### Zero-Trust Principles
Verify explicitly → Always authenticate and authorize based on all available data (user, location, device, risk)
Use least privilege → Give only the minimum access required for a task
Assume breach → Always operate as if the system is already compromised and limit damage

```
- Just-In-Time (JIT) - Access is granted only when needed and for a limited time
- Just-Enough-Access (JEA) - Users get only the exact permissions required for their task
```

Zero-Trust Pillars
- Identity - Verify and secure every user identity continuously
- Devices - Ensure devices are healthy, compliant, and trusted before access
- Applications - Control and monitor permissions and user actions within apps
- Data - Protect data using encryption and strict access control
- Infrastructure - Monitor systems for threats, detect attacks, and respond quickly
- Network - Encrypt all communication and secure traffic flow
### Defense of Depth
Defense in Depth in Microsoft Azure is a security strategy that uses multiple layers of protection to secure systems and data. The idea is that if one layer fails, other layers still provide protection.
Instead of relying on a single security measure, security is applied at every level—from physical hardware to identity, applications, and data.

Example:
a firewall blocks unwanted traffic, users must log in through Microsoft Entra ID, permissions control what they can do, and data is encrypted so it stays safe even if someone gets access.
### Microsoft Defender for Cloud
Microsoft Defender for Cloud is a security service in Microsoft Azure that helps you protect, monitor, and improve the security of your cloud resources.
It continuously checks your environment for security risks, vulnerabilities, and misconfigurations, and gives recommendations to improve security.
