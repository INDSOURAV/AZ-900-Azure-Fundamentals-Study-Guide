### What is Cloud Computing?
Cloud computing means using someone else’s powerful computers over the internet to store data, run applications, or process information instead of using your own physical hardware, and paying only for the resources you use.
Computing resources, you can use from cloud computing:
- windows and Linux servers
- unlimited file storage
- databases
- message queues
- content delivery network
- batch processing jobs

```
Azure Service:

Web App: A Web App in Microsoft Azure is a cloud service that allows you to build, host, and run web applications without managing servers or infrastructure.
Example: If a company wants to host a website or web application, they can deploy it on Azure Web App instead of buying and maintaining their own servers.

Function App: A Function App in Microsoft Azure is a service that allows you to run small pieces of code (functions) without managing servers.
Example: When a file is uploaded to storage, an Azure Function automatically processes the file without running a full server.

Logic App: A Logic App in Microsoft Azure is a cloud service that helps you automate workflows and integrate different applications or services without writing much code.
Example: When an email with an attachment arrives, the Logic App automatically saves the file to cloud storage and notifies the team.

Container: A container is a lightweight package that includes an application and everything it needs to run, such as code, libraries, and dependencies, allowing it to run consistently across different environments.
Example: A developer packages a Node.js web application and its dependencies into a Docker container and deploys it to Azure to run the application.
```

### Shared Responsibility Model
The Shared Responsibility Model defines how security and management responsibilities are divided between the cloud provider and the customer. In cloud computing, the provider secures the cloud infrastructure, while the customer is responsible for securing their data, applications, and configurations. This model helps ensure that both parties clearly understand their security roles in the cloud.
##### On Premises Responsibility
In an on-premises environment, the organization is responsible for all parts of the IT infrastructure and security. This means the company must manage the physical building, hardware, network, operating systems, applications, and data security themselves.

1. Building Security: 
   The organization must secure the physical building or data center where servers and equipment are located. This includes locks, surveillance cameras, and access control systems.
2. Physical Network Security: 
   The company must protect network cables, routers, and switches from physical tampering or unauthorized access.
3. Physical Computer Security:
   Servers and computers must be physically protected from theft, damage, or unauthorized access.
4. Operating System Patches:
   The organization is responsible for installing and managing operating system updates and security patches on all servers and computers.
5. Network and Firewall Settings:
   The IT team must configure firewalls, network rules, and security policies to protect the internal network from cyber threats.
6. Application Settings:
   Applications must be configured securely, including managing permissions, updates, and vulnerabilities.
7. Authentication Platform:
   The organization must manage systems used for user authentication, such as identity management and login systems.
8. User Accounts:
   IT administrators must create, manage, and secure user accounts to prevent unauthorized access.
9. Devices:
   All devices like computers, servers, and laptops must be maintained, updated, and secured by the organization.
10. Data:
    The organization is responsible for protecting, backing up, and controlling access to its data to prevent loss or breaches.

### Public Cloud, Private Cloud, Hybrid Cloud
##### Public Cloud
The public cloud is defined as computing services offered by third-party providers over the internet, making them available to anyone who wants to use or purchase them, such as Microsoft Azure Public Cloud.
##### Private Cloud
The private cloud is defined as computing services offered either over the internet or a private internal network and only to select users instead of the general public.
Looks and acts like a cloud, except customer owns or leases or has exclusive access to the hardware.

```
Even if the cloud hosted by third party, but the underlying hardware is dedicated solely to you and not shared with others, it is still considered as a private cloud such as Azure Government Cloud

Azure Stack HCI/ Azure Local:
A solution from Microsoft Azure that allows organizations to run Azure services on their own on-premises data centers.
It is a hybrid cloud solution that enables companies to use Azure technologies locally while still connecting to Azure for management, monitoring, and additional services.
Example: A bank wants to keep customer data inside its own data center to meet security and compliance requirements, but it still wants the benefits of Azure cloud services.

Azure Arc: 
Azure Arc extends Azure management and services to on-premises, edge, and multi-cloud environments, letting you manage servers, Kubernetes clusters, and databases consistently across all locations.
Azure Arc is a service that extends Azure management and governance to resources running outside Azure.
```
##### Hybrid Cloud
A hybrid cloud is a computing environment that combines a private cloud with a public cloud.
Example: A company might store sensitive customer data in its private data center while running web applications or analytics in Microsoft Azure or Amazon Web Services.
##### Comparison Matrix
1. Cost:
   In a Public Cloud, the cost is usually lower because organizations pay only for the resources they use without purchasing hardware. In a Private Cloud, the cost is higher since the organization must buy, maintain, and manage its own infrastructure. A Hybrid Cloud has a moderate cost because it combines both private infrastructure and public cloud services.
   
2. Ownership:
   In a Public Cloud, the infrastructure is owned and managed by cloud providers such as Microsoft Azure or Amazon Web Services. In a Private Cloud, the infrastructure is owned and managed by a single organization. In a Hybrid Cloud, ownership is shared between the organization and the cloud provider.
   
3. Access:
   A Public Cloud is accessible over the internet and can be used by multiple organizations. A Private Cloud has restricted access and is used only by one organization. In a Hybrid Cloud, some resources are private while others can be accessed through the public cloud.
   
4. Scalability:
   Public Clouds offer very high scalability, allowing organizations to increase or decrease resources easily. Private Clouds have limited scalability because they depend on the organization’s hardware capacity. Hybrid Clouds provide flexible scalability by using both private and public cloud resources.
   
5. Core Value:
   The main value of a Public Cloud is cost efficiency, flexibility, and fast deployment. The Private Cloud focuses on security, control, and compliance. A Hybrid Cloud provides a balance of security, flexibility, and scalability by combining the advantages of both environments.
### Cloud Pricing
When you use services in Microsoft Azure, the cost is calculated based on several factors such as the type of service, configuration, usage, and region. Different services have different pricing components depending on how resources are used.

Factors Affecting Virtual Machine Pricing
For a Virtual Machine (VM), the cost depends on multiple factors:
- Geographical Region: Prices vary depending on the data center location where the VM is deployed.
- Operating System: Windows VMs usually cost more than Linux VMs because of licensing fees.
- Instance Size: Larger VM sizes with more CPU and RAM cost more.
- Disk Type and Size: Premium SSD, Standard SSD, or HDD storage affects the price.
- Bandwidth: Data transferred out of Azure can add additional charges.
- Backup Storage: Using backup services increases storage costs.
- Reservation / Savings Plan: Committing to longer usage (1 or 3 years) can reduce the price.
- Support Agreement: Higher-level Azure support plans can add additional cost.

Factors Affecting Azure Cosmos DB Pricing
Pricing for Azure Cosmos DB depends on the following factors:
- API Choice: Different APIs (Core SQL, MongoDB) may affect cost.
- Region: The number and location of regions where the database is deployed.
- Standard Model or Serverless: Serverless charges based on usage, while provisioned throughput charges for reserved capacity.
- Operations Per Second: The number of read and write operations performed.
- Consumed Storage: The amount of data stored in the database.
- Optional Dedicated Gateway: Additional gateway resources increase cost.
- Backup Storage: Continuous backup or periodic backup storage adds cost.

How Azure Charges for Services
Azure pricing usually falls into a few main categories:
- Pay for Time
  You are charged based on how long the resource is running.
  Example: Virtual Machines are charged per second or per hour while they are running.
  
- Pay for Storage (GB)
  You are charged based on the amount of data stored.
  Example: Storage services may charge around $0.02 per GB per month depending on storage type.
  
- Pay for Operations
  You are charged based on the number of operations or requests performed.
  Example: Database reads/writes or storage transactions in services like Azure Cosmos DB.
