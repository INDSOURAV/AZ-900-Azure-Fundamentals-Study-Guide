### Overview Of Azure Storage
Azure Storage in Microsoft Azure is a Infrastructure as a Service (IaaS) used to store data in the cloud in a secure, scalable, and highly available way.

It is designed to handle different types of data such as files, images, videos, backups, and structured or unstructured data. Azure manages the underlying infrastructure, so you don’t need to worry about disks or hardware.

Azure Storage provides multiple types of storage services. Blob Storage is used for unstructured data like images and videos, File Storage provides shared file access similar to a network drive, Queue Storage is used for messaging between applications, and Table Storage is used for structured NoSQL data.
### Container (Blob) Storage
Azure Blob Storage in Microsoft Azure is a service used to store large amounts of unstructured data, such as images, videos, documents, backups, and logs. “Unstructured” means data that does not follow a fixed format like tables (unlike databases).

The data is organized in a simple structure: a Storage Account contains multiple containers, and each container holds multiple blobs (the actual files). A container is similar to a folder, and a blob is the file itself. You can upload, download, and manage these files over the internet or through private access.
##### Redundancy (Azure Storage)
Redundancy in Azure Storage means Azure keeps multiple copies of your data to protect it from failures and ensure high availability.
By default, Azure stores 3 copies of your data within a region. This can be either:
- Stored within a single data center (Locally Redundant) Or spread across multiple Availability Zones (Zone-Redundant)
This ensures your data is safe even if hardware fails.

For higher protection, Azure also offers global redundancy, where it keeps 6 copies of your data:
- 3 copies in the primary region
- 3 copies in another paired region
This helps protect against regional failures, while also following data sovereignty laws (data stays within the same geographic area).
##### Access Tiers
- Hot Tier
  The Hot tier in Azure Blob Storage is used for data that is frequently accessed. It has a higher storage cost but lower access cost, making it ideal for active data that is read or modified often. This tier is best suited for scenarios like website content, frequently used files, or active application data where quick and regular access is required.
- Cool Tier
  The Cool tier is designed for data that is accessed occasionally, typically less than once every 30 days. It offers a lower storage cost than the Hot tier, but the cost to access the data is higher. It is suitable for short-term backups or files that are not used regularly but still need to be available when required.
- Cold Tier
  The Cold tier is meant for data that is rarely accessed but still needs to be available without significant delay. It has an even lower storage cost compared to the Cool tier, but higher access costs. This tier is useful for long-term storage scenarios where data is kept for compliance or reference but is not accessed frequently.
- Archive Tier
  The Archive tier in Azure Blob Storage is used for data that is almost never accessed. It has the lowest storage cost, but when you need the data, it must first go through a process called rehydration, which takes time and has higher access cost. Because of this delay, it is best used for long-term backups, historical data, or records that must be stored for years but are rarely needed.
##### Failover
Failover in Microsoft Azure is the process of automatically switching from a failed system or resource to a backup system to keep applications running.
Example: 
In Microsoft Azure, a simple failover example with disks is when a Virtual Machine disk is stored with redundancy (like multiple copies), If the primary disk hardware fails:
- Azure automatically switches to another replica copy of the disk
- The VM continues running using the backup copy
This switch from the failed disk to a healthy copy is called failover.
### AZCOPY
AzCopy is a command-line tool provided by Microsoft Azure to transfer data quickly and securely to and from Azure Storage.

It is optimized for high-performance data movement, which means it can handle large files and large volumes of data efficiently. AzCopy supports services like Blob Storage and File Storage, and uses secure methods such as access keys or shared access signatures (SAS) for authentication.
AzCopy is commonly used in real-world scenarios where data needs to be moved between environments. Common use cases include:
- Copying data from an on-premises system to an Azure storage account (e.g., uploading backups to the cloud)
- Copying data from an Azure storage account to an on-premises system (e.g., downloading data for local processing)
- Copying data from one Azure storage account to another (e.g., migration or replication between regions)

Example:
A company wants to move its local backup files to the cloud. Instead of uploading manually, they use AzCopy to quickly transfer all files from their local system to Azure Blob Storage, saving time and effort.
### Azure Files and Azure File Sync
##### Azure Files
Azure Files in Microsoft Azure is a service that provides fully managed file shares in the cloud. It supports a true hierarchical structure with folders, just like a traditional file system, making it easy to organize data.

It works like a network drive, where you can store files and access them from multiple machines using standard protocols like SMB or NFS, just like a shared folder in an office.
You can also mount this storage to a server or local machine using a drive letter (like Z:), so it behaves exactly like a network drive on your system.

Example:
A company stores shared documents in Azure Files and maps it as a drive on employee systems. Users can access and manage files just like they would on a local shared folder.
##### Azure File Sync
Azure File Sync is a service that connects your on-premises file server with Azure Files, keeping data synchronized between them.
It allows you to:
- Keep frequently used files locally on your server
- Store less-used files in the cloud (Azure Files)
- Access the same data from both locations

Example:
A company has a local file server in the office. With Azure File Sync:
- Employees access files locally (fast access)
- Data is also synced to Azure for backup and remote access
### Azure Migrate
Azure Migrate is a service in Microsoft Azure that helps organizations move their on-premises workloads to Azure in a planned and controlled way.

It is not a single tool, but a collection of tools used to discover, assess, and migrate servers, databases, applications, and even virtual desktops.
##### How it Works (Simple Flow)
First, you create a migration project in the Azure portal. Then you install a discovery tool inside your local environment (on-premises network). This tool scans your systems and collects information about servers, applications, and performance.
Next, Azure Migrate performs an assessment, which checks whether workloads are compatible with Azure and also provides cost estimates and readiness reports. After that, you can perform the actual migration using services like Azure Site Recovery or Database Migration Service.
### Azure Data Box
Azure Data Box is a service in Microsoft Azure used to physically transfer large amounts of data to the cloud when uploading over the internet is too slow or impractical.
It is mainly used when organizations have huge datasets (terabytes or petabytes) and normal internet upload would take days or weeks. Instead of transferring data online, Microsoft sends you a secure physical device, you copy your data into it, and then ship it back.

Once Microsoft receives the device, they upload the data directly into your Azure environment. The data is always encrypted during transfer and storage for security.
Example:
A company has 10 TB of backup data. Uploading it over the internet would take many days, so they use Azure Data Box instead. Microsoft sends a device, the company loads the data, ships it back, and the data is uploaded to Azure in a few days.
