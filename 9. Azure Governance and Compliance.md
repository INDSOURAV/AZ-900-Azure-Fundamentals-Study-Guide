Governance and Compliance in Microsoft Azure is about defining rules, policies, and processes for how resources should be used, and then ensuring those rules are followed.
Governance comes from the idea of control and oversight—just like in a company where leadership sets rules (security, IT, legal), in Azure you also define rules such as:
- Which services are allowed
- What configurations are required
- How security and backups should be handled
Compliance means making sure those rules are actually followed, not just written down.
##### Why Governance is Important
In real-world environments, there can be hundreds or thousands of resources, so without governance:
- Security risks increase
- Costs can go out of control
- Standards are not followed
- Systems become inconsistent

For example, rules could include:
- Only approved OS versions are allowed
- Backups must run every 24 hours
- Certain ports must not be open
- Only specific users can access sensitive resources
##### How Azure Enforces Governance
Azure provides tools to automate and enforce these rules, instead of relying on manual checks:
1. Azure Policy
   Allows you to define and enforce rules across resources.
   Example: Block creation of outdated servers or require tags.
2. Resource Locks
   Prevent accidental deletion or modification of critical resources.
   You must remove the lock before making changes, adding an extra safety layer.
3. Role-Based Access Control (RBAC)
   Controls who can do what by assigning permissions.
   Follows the principle of least privilege (give only required access).
4. Templates (ARM / Template Specs)
   Used to standardize deployments, ensuring resources are created with the correct configuration every time.
5. Microsoft Purview
   Helps manage and protect data governance, including data security, compliance, and usage policies.
### Azure Policy
Azure Policy in Microsoft Azure is used to define, enforce, and monitor rules across your resources so everything stays compliant with your organization’s standards.
You can apply these rules at different levels:
- Subscription
- Resource Group
- Individual Resources

Example:
1. Enforce Rules (Control Creation)
   You can block resources that don’t meet your standards.
   Example:
	- Only allow certain VM sizes
	- Restrict deployments to specific regions (like only Europe)
	- Block certain services (e.g., no Web Apps allowed)
2. Audit Compliance (Monitor Only)
   You can check which resources are violating rules without blocking them.
   Example:
	- Find resources without tags
	  Detect outdated SQL Server versions
3. Apply or Inherit Tags Automatically
   You can:
	- Add missing tags
	- Inherit tags from resource groups
4. Restrict Configurations
   You can control how resources are configured.
   Example:
	- Allow only specific storage types (SKUs)
	- Enforce minimum software versions
	- Limit high-cost VM sizes
5. Limit Locations (Region Control)
   You can restrict where resources are created.
   Example:
	- Only allow deployment in EU regions for compliance
### Resource Locks
Resource Locks in Microsoft Azure are used to protect important resources from accidental or unauthorized changes or deletion. They act as an extra safety layer, especially for production environments, where mistakes can be costly.
##### What Resource Locks Do
When you apply a lock to a resource, it restricts what actions can be performed, even if users already have permissions. This means users can still access the resource, but critical actions are blocked unless the lock is removed.
##### Types of Resource Locks
1. Read-Only Lock
   This is the most restrictive type. It prevents any modification to the resource.
	- You cannot change configurations
	- You cannot resize or update resources
	- It also prevents deletion
	Example: A Virtual Machine cannot be resized or modified if a read-only lock is applied.
2. Delete Lock (Do Not Delete)
   This allows changes but prevents deletion only.
	- You can modify configurations
	- But you cannot delete the resource
	Example: You can update a storage account, but you cannot delete it.

```
Locks apply to everyone, including: 
- Resource owners
- Administrators

No one can bypass the lock unless they remove it first, and only users with proper permissions can remove locks.
```
### Microsoft Purview
Microsoft Purview is a centralized data governance solution in Microsoft Azure that helps organizations discover, protect, monitor, and manage their data across the entire environment.
It acts like a single dashboard for all data-related policies and risks, helping you understand:
- Where your data is
- How sensitive it is
- Who is accessing it
- How it is being used or shared
